# 项目规则

## 1. 避免 BOM

PowerShell 写 UTF-8 文件时必须在开头指定 `-Encoding UTF8NoBOM`，禁止使用 `Set-Content -Encoding UTF8` 或 `Out-File`（默认带 BOM）。HTML/JS/CSS 文件不允许出现 BOM 字符 U+FEFF。

## 2. JavaScript 修改后必须做语法检查

任何对 `.html` 内嵌 `<script>` 或独立 `.js` 文件的修改，在保存后必须用 `node --check <file>` 验证 JavaScript 语法，确认无错误后才能启动/重启服务器。

## 3. 长指令必须分割执行

用户给出的指令如果涉及多个独立变更，必须先拆分成多个独立板块，每次只完成一个板块。

分割原则：
- 每个板块只改一个东西（如：CSS、HTML 结构、JS 逻辑）
- 板块之间不能有依赖

## 4. 每完成一个板块必须验证汇报

每完成一个独立板块（包括但不限于：一个功能、一个 bug 修复、一个样式调整），必须：

1. 进行错误检查（语法检查、结构验证等）
2. 向用户汇报完成内容
3. 等待用户确认同意后，才能继续下一个板块

未经用户同意，不得连续执行多个板块。

## 5. 操作用户数据前保留默认备用

读取 `localStorage` 时，如果 `dishes`/`categories` 为空数组，应回退到默认数据（`DC`），而不是直接展示空列表。`sd()` 保存数据不得覆盖 `dishes`/`categories` 的默认值。

## 6. 结构性修改前必须向用户申请同意

涉及以下任何一项变更时，必须先向用户提交中文方案说明，获得同意后才能实施：

- 页面结构重组（移动/新增/删除 HTML 骨架区块）
- JavaScript 事件处理流程变更（如把事件从函数内移到全局）
- 新增需要改动多个文件或模块的功能
- 需要同时修改 CSS + HTML + JavaScript 的复合功能

方案应简要说明：改什么、为什么改、预期效果。用户同意后，按规则 3 分步实施。
