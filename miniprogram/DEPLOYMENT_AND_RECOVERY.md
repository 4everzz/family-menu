# 小家菜单部署与恢复手册

> 适用版本：`v1.1.0` 及以后  
> 云环境：`cloud1-d2gua37h7753f3812`  
> 最后更新：2026-07-29

这份手册用于发布新版本、发生误操作或更换电脑时恢复项目。操作前先区分两件事：

- **部署**：把本地已验证的代码发布到小程序、云函数或 Web 后台。
- **恢复**：把错误状态回退到可用状态。恢复前必须先备份当前状态，防止越修越乱。

当前项目没有自动“整库一键恢复”功能。订单、库存和权限具有业务关联，直接把 JSON 覆盖写回数据库风险很高；恢复时应按本手册分场景处理。

## 1. 系统组成与部署位置

| 部分 | 当前技术 | 部署位置 | 是否需要单独服务器 |
| --- | --- | --- | --- |
| 顾客点餐与店铺现场管理 | 微信原生小程序 | 微信开发者工具上传体验版/正式版 | 不需要 |
| 业务后端 | 微信云开发云函数 | 云开发环境中的 `cloudfunctions` | 不需要 |
| 业务数据 | 云开发文档型数据库 | 云开发环境数据库集合 | 不需要 |
| 菜品、头像、备份文件 | 云开发云存储 | 云开发环境云存储 | 不需要 |
| 平台超级管理员后台 | Vue 3 + Vite 静态站点 | 云开发静态网站托管 | 不需要 |

因此，本项目没有单独购买 CVM 云服务器。云函数是“按调用运行的后端代码”，静态托管是“放网页文件的空间”。

## 2. 发布前检查

每次发布前按以下顺序检查：

1. 在 Git 中确认当前代码可追溯：记录准备发布的提交号，例如执行 `git log -1 --oneline`。
2. 在 Web 超管后台的“数据备份”中，为重要店铺生成并下载一份 JSON 备份。
3. 记录本次会改动的范围：小程序、哪些云函数、是否包含 Web 后台。
4. 在微信开发者工具中确认选中正确云环境：`cloud1-d2gua37h7753f3812`。
5. 先在开发者工具重新编译；涉及下单、库存、角色或订单处理时，还要用体验版真机测试。

**不要做的事**：不要在未确认云环境时部署云函数；不要把 `AppSecret`、Web 管理员密码、Token 或临时访问链接写进代码和 Git；不要把开发环境函数部署到正式环境。

## 3. 正常部署流程

### 3.1 只修改小程序页面

适用：WXML、WXSS、页面 JavaScript、工具函数等变更，且未修改 `cloudfunctions`。

1. 微信开发者工具打开 `E:\AI\menu\miniprogram`。
2. 重新编译，检查控制台没有 WXML/JavaScript 错误。
3. 在体验版完成本次功能的真机测试。
4. 点击“上传”，填写版本号和更新说明，提交体验版或审核。

### 3.2 修改云函数

当前云函数及职责：

| 云函数 | 部署时重点检查 |
| --- | --- |
| `auth` | 登录、用户资料、超级管理员身份 |
| `shop-access` | 店铺/桌码扫码进入、当前店会话 |
| `shop-admin` | 店铺设置、桌位、成员授权 |
| `admin-menu` | 菜单、库存、下单、订单处理、统计 |
| `web-admin` | Web 超管后台登录、跨店管理、报表、备份 |

部署步骤：

1. 在开发者工具左侧“云开发”确认环境 ID 正确。
2. 在 `cloudfunctions` 中只对本次有修改的云函数点击“上传并部署：云端安装依赖”。
3. 等待部署完成后重新编译小程序。
4. 至少验证该函数对应的一条关键流程。例如改了 `admin-menu`，就验证点菜、下单和后台完成订单；改了 `shop-access`，就验证店铺码和桌码进入。
5. 若云函数提供 HTTP 访问服务（当前为 `web-admin`），还要打开 Web 后台确认请求正常。

建议顺序：**先部署云函数，再上传小程序体验版**。这样新小程序不会调用一个尚未更新的后端接口。

### 3.3 修改 Web 超级管理员后台

适用目录：`E:\AI\menu\web-admin-frontend`。

1. 在该目录执行 `npm run build`。
2. 确认生成 `dist` 文件夹，且构建没有报错。
3. 云开发控制台 → 静态网站托管 → 打开已有 Web 应用。
4. 覆盖上传 `dist` 内的全部文件，包括 `index.html` 和 `assets` 文件夹；不要删除已有应用后重新创建。
5. 打开正式后台网址，按 `Ctrl + F5` 强制刷新浏览器缓存。
6. 登录后检查本次修改的页面。若同时改了 `web-admin` 云函数，先部署云函数，再上传 `dist`。

当前正式后台地址：`https://cloud1-d2gua37h7753f3812-1454825551.tcloudbaseapp.com`

## 4. 备份说明

### 4.1 现有 Web 备份包含什么

在 Web 超管后台“数据备份”中，可按店铺和日期范围生成 JSON。备份会写入云存储 `shop-backups/{shopId}/`，并在 `shop_backups` 集合中记录元数据。

备份包含：

- 店铺设置；
- 该店分类、菜品和库存字段；
- 该店桌位；
- 所选日期范围内的订单快照。

单次限制：最多 31 天、5000 笔订单。

### 4.2 现有 Web 备份不包含什么

- `users` 用户资料与系统用户 ID；
- `shop_members` 店铺成员和管理员关系；
- `shop_entry_sessions` 顾客扫码会话；
- 菜品图片的实际二进制文件。

菜品图片在备份中只保留云存储文件 ID。因此删除云存储图片前必须额外确认；仅有 JSON 文件无法重新生成被删除的图片。

### 4.3 推荐的手动备份动作

在版本发布、批量改菜单、调整管理员关系之前：

1. Web 后台生成并下载每个关键店铺的 JSON。
2. 将下载的 JSON 放在本机非项目目录，例如 `E:\MenuBackups\2026-07-29\`。
3. 在云开发控制台的数据库页面，单独导出 `users`、`shop_members`；这些数据不在店铺 JSON 备份中。
4. 若计划删除很多菜品图片，在云存储中确认对应文件仍可找到，必要时额外下载图片目录。

## 5. 恢复场景

### 场景 A：新版本页面报错，但数据正常

这是最常见、风险最低的情况。不要动数据库。

1. 停止继续上传新版本。
2. 找到上一个正常 Git 提交：`git log --oneline`。
3. 在新分支或本地工作区恢复对应代码，由开发者重新编译验证。
4. 若只涉及 Web 后台，重新构建旧版本 `dist` 并覆盖上传静态托管。
5. 若涉及云函数，重新部署旧版本对应函数；随后重新编译并上传小程序。

**注意**：不要使用 `git reset --hard` 直接覆盖当前工作区，避免丢失未提交修改。优先通过提交记录恢复指定文件或让开发者处理。

### 场景 B：误改了菜品、分类、桌位或店铺设置

1. 立刻生成一份“错误发生后”的备份，用于保留现场证据。
2. 下载错误发生前最近的一份 JSON，确认其中店铺名称、菜品和桌位数量正确。
3. 先在测试店人工核对恢复字段，再回填正式店的数据。
4. 菜品图片只在云存储文件仍存在时可恢复显示；若图片已物理删除，需要重新上传。
5. 恢复后在顾客侧检查菜单，在管理员侧检查库存和桌码。

当前项目没有自动 JSON 导入功能。因为库存与订单可能已经发生变化，直接覆盖会把新订单之后的库存状态冲掉。遇到大批量误删时，应先停止接单，再由开发者编写一次性、可审计的恢复脚本。

### 场景 C：订单、库存或营业额异常

1. 先在店铺设置关闭“接单开关”，阻止新的订单继续写入。
2. 不要直接修改订单金额、订单状态或剩余库存。
3. 导出该店异常日期范围的订单备份，并保留截图和订单编号。
4. 对照订单状态：只有“已完成”订单应计入营业额；“已取消”订单在当天应恢复库存。
5. 确认原因后再做最小范围修复，修复完成后重新打开接单开关。

### 场景 D：删除了用户或管理员权限异常

1. 不要依赖店铺 JSON 备份，因为它不包含完整用户与成员关系。
2. 在云开发数据库核对 `users` 与 `shop_members` 两个集合。
3. 超级管理员可通过 Web 后台重新授予店铺管理员；超级管理员身份问题则由现有超级管理员在 `users` 中核对后处理。
4. 修改后，让目标用户彻底关闭并重新打开小程序，重新读取身份。

### 场景 E：云函数、静态托管或整个环境无法访问

1. 先检查云开发控制台的环境状态、套餐状态和欠费通知。
2. 检查最近是否部署了云函数或覆盖上传了 Web 文件；若有，优先按场景 A 回退代码。
3. 云函数异常：查看该函数日志，记录报错时间、函数名和请求动作，不要反复盲目部署。
4. Web 后台异常：确认 `web-admin` 函数 HTTP 地址未变、静态托管 `dist` 上传完整，并用强制刷新排除浏览器缓存。
5. 数据库或云存储不可用：暂停接单，保留现有备份文件，联系云开发支持后再决定是否恢复或迁移。

## 6. 更换电脑或重新搭建开发环境

1. 安装 Git、Node.js LTS、微信开发者工具。
2. 克隆 Gitee 仓库：`https://gitee.com/zmeety/first-codebase.git`。
3. 用微信开发者工具导入 `miniprogram` 目录，不是项目根目录。
4. 选择正确小程序 AppID 和云环境 `cloud1-d2gua37h7753f3812`。
5. 进入 `web-admin-frontend` 执行 `npm install`，再执行 `npm run build` 验证 Web 前端可构建。
6. 不要从 Git 寻找云数据库数据、云存储图片或后台密码：它们不应提交到仓库，应在云开发控制台或安全的密码管理工具中保管。

## 7. 发布后的最小验收清单

- [ ] 顾客扫码店铺码或桌码后能看到正确菜单。
- [ ] 顾客可以加购、提交订单；未扫码桌码时会被正确拦截。
- [ ] 管理员可以看到订单，完成和取消订单状态正确。
- [ ] 一级管理员与二级管理员的管理范围正确，普通顾客不显示管理入口。
- [ ] Web 超管后台可以登录、读取店铺和订单。
- [ ] 本次涉及的图片、菜单或报表能正常加载。
