# 微信云开发说明

## 云环境

当前环境 ID：`cloud1-d2gua37h7753f3812`

小程序不直接依赖云数据库的业务权限判断。前端通过 `wx.cloud.callFunction` 调用云函数；云函数从微信 OpenID、店铺成员关系和当前扫码会话中重新校验身份与 `shopId`。

## 云函数

| 云函数 | 主要职责 |
| --- | --- |
| `auth` | 微信登录、用户资料、全局超级管理员身份。 |
| `shop-access` | 店铺码/桌码进入、扫码会话、当前店铺快照和我的店铺。 |
| `shop-admin` | 店铺营业规则、店铺码、桌位码、店铺成员管理。 |
| `admin-menu` | 菜单、分类、库存、顾客订单、店铺订单处理和店铺统计。 |
| `web-admin` | Web 超管后台登录、跨店管理、报表、订单导出与数据备份。 |

## 云数据库集合

| 集合 | 用途 |
| --- | --- |
| `users` | 微信用户、随机用户 ID、昵称、头像、启用状态和全局角色。 |
| `shops` | 店铺信息、营业规则、接单开关、店铺码和数据版本。 |
| `shop_members` | 用户与店铺的成员关系、一级/二级管理员权限。 |
| `shop_tables` | 桌位、固定桌码、启停状态与展示名称。 |
| `shop_entry_sessions` | 顾客扫码后获得的短期店铺/桌位会话。 |
| `categories` | 按 `shopId` 隔离的菜品分类。 |
| `dishes` | 按 `shopId` 隔离的菜品、每日库存和云存储图片文件 ID。 |
| `orders` | 订单快照、状态、取消原因、订单金额和创建时间。 |
| `shop_backups` | Web 后台生成的数据备份元数据。 |

## 订单与库存规则

订单状态为“制作中”“已完成”“已取消”。下单时，`admin-menu` 在云数据库事务内校验库存、扣减库存并写入订单；同一个 `requestId` 重复提交会复用原订单，避免产生重复订单。

取消仅允许制作中订单。当天取消会在同一事务中恢复库存；跨天库存已经按每日规则重置，因此不回补旧订单数量。营业额、完成客单价、热销菜品和排行只累计已完成订单。

## 安全核对

1. 云数据库集合不可设置为“所有用户可读写”。
2. 因当前小程序不直接调用 `wx.cloud.database()`，应优先使用严格的客户端数据库权限，关键读写一律通过云函数。
3. 云函数内必须继续以 OpenID、成员关系和 `shopId` 为准，前端传来的角色或店铺 ID 不能直接信任。
4. 云存储文件 ID 可存数据库；临时访问 URL 会过期，不能当作永久图片地址保存。
